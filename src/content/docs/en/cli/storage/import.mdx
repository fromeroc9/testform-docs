---
title: "testform import"
---

```bash
# Mode A: Remote Issue Binding
testform [global options] import [options] <address> <remote-id>

# Mode B: Test Execution Results Ingestion (Runner Bridge)
testform import -results=<file> [options]
testform import <file.xml|json> [options]
```

The `testform import` command serves two foundational purposes in Test-as-Code orchestration:
1. **Remote Issue Import:** Brings existing external issue tracker items (such as GitHub Issues created manually in the web UI prior to adopting Testform) under declarative management **without destroying or recreating them**.
2. **CI/CD Results Ingestion (Runner Bridge):** Ingests test result artifacts generated by industry-standard runners (**Jest, PyTest, Playwright, Cypress, Cucumber, JUnit 4/5, Mocha**) and synchronizes them directly into `.run.feature` specifications with canonical `* set` syntax.

---

## Mode A: Remote Issue Import

### Options

| Option | Default | Description |
| :--- | :--- | :--- |
| `-scope=<scope>` | `testcase` | Target scope (`testcase`, `testrun`, or `testplan`). |
| `-lock=false` | `true` | Disables state locking during import. |
| `-no-color` | `false` | Disables colored console output. |

### Example
```bash
testform import -scope=testcase "auth.case.feature.@tc-5" 104
```

---

## Mode B: Test Results Ingestion (Runner Bridge)

Seamlessly connect your automated CI/CD pipelines to Testform with zero proprietary runner plugins.

### Supported Formats with Auto-Detection
- **JUnit XML:** Detected via `.xml` extension or `<testsuites>` / `<testsuite>` root elements. Works with PyTest, Jest (junit-reporter), Cypress, JUnit 5, NUnit.
- **Playwright JSON:** Detected via nested `suites -> specs -> tests -> results` structure.
- **Cucumber JSON:** Detected via BDD feature and scenario matrices.

### Ingestion Options

| Option | Default | Description |
| :--- | :--- | :--- |
| `-results=<path>` | Required (or positional argument) | Path to test results report (`.xml` or `.json`). |
| `-target=<path>` | Auto | Existing `.run.feature` file to update in-place. |
| `-out=<path>` | `testruns/import-YYYYMMDD.run.feature` | Target file destination when generating a new run. |
| `--auto-create-bugs` | `false` | Automatically generates bug specifications (`@bg-*`) in `.bug.feature` for each failed test. |

### In-Place Run Updates (`-target`)
If you have a run already declared in `tests/sprint_12.run.feature` and want to update scenario outcomes from CI:
```bash
testform import -results=junit.xml -target=tests/sprint_12.run.feature
# or simply:
testform import junit.xml -target=tests/sprint_12.run.feature
```

Testform matches each scenario by its `@tc-*` target tag and updates or injects `* set` statements:
```gherkin
@tr-01
Scenario: tests/auth/login.case.feature.@tc-01
  * set status = passed
  * set duration = 1.14s
  * set target = tests/auth/login.case.feature.@tc-01
```

---

## Exit Codes

- `0`: Resource or execution report imported successfully.
- `1`: Remote issue not found or error parsing results report.
