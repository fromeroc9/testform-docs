---
title: "testform workspace"
---

```bash
testform workspace <subcommand> [options] [args]
```

The `testform workspace` command manages separate working states (workspaces) within the same configuration directory.

Workspaces allow you to manage both **persistent environments** (such as `staging`, `production`, `qa-env-1`, or `release-2.0`) and **ephemeral sandboxes** (for PRs, feature branches, or disposable exploratory QA testing) using the **exact same `.feature` test files**, with completely isolated state files and remote issues.

> [!NOTE]
> Capabilities previously provided by `testform ephemeral` are now fully unified into `testform workspace` via the `-ephemeral` flag.

---

## Workspace Types

1. **🏛️ Persistent (Default):** Long-lived environments (`default`, `staging`, `production`). State is preserved indefinitely until explicitly deleted.
2. **🧪 Ephemeral (`-ephemeral`):** Disposable sandboxes with a bounded lifecycle. Enables isolated test execution without polluting the `default` environment or leaving orphaned issues in Jira/GitHub, featuring TTL (Time-To-Live) support and promotion into `default`.

---

## Subcommands

### 1. `testform workspace list`
Lists all active workspaces in an enriched table displaying type, tracked resource count, and remaining TTL:

```bash
$ testform workspace list

Active Workspaces (3):
  WORKSPACE            TYPE          RESOURCES    TTL REMAINING
  ───────────────────  ────────────  ───────────  ────────────────────
* default              🏛️ Persistent  24           Infinite (Official)
  pr-412-sandbox       🧪 Ephemeral   8            ⏳ 1h 35m remaining
  staging              🏛️ Persistent  24           Infinite
```

The green asterisk `*` indicates the currently active workspace.

---

### 2. `testform workspace new <name> [options]`
Creates a new, empty workspace and immediately switches to it:

```bash
# Create a standard persistent workspace:
$ testform workspace new release-2.0

# Create a disposable ephemeral sandbox:
$ testform workspace new pr-412-sandbox -ephemeral

# Create an ephemeral sandbox with a custom Time-To-Live (TTL):
$ testform workspace new pr-412-sandbox -ephemeral -ttl=2h
```

**Options:**
- `-e`, `-ephemeral`: Flags the workspace as a disposable ephemeral sandbox.
- `-ttl=<duration>`: Specifies the lifespan of the ephemeral sandbox (e.g., `30m`, `2h`, `1d`).

Ephemeral output:
```text
🚀 Initializing ephemeral QA workspace: pr-412-sandbox
   Isolated state: testform.state.d/pr-412-sandbox/testform.state

✔ Ephemeral workspace "pr-412-sandbox" successfully created and activated!
   All testform commands will now safely execute in this sandbox.
```

---

### 3. `testform workspace select <name>`
Switches context to an existing workspace (persistent or ephemeral):

```bash
$ testform workspace select pr-412-sandbox
Switched to workspace "pr-412-sandbox".
```

Once selected, all subsequent Testform commands (`plan`, `apply`, `report`, Studio) automatically operate within this workspace.

---

### 4. `testform workspace show [name]`
Displays detailed metadata and managed resources for the workspace:

```bash
$ testform workspace show pr-412-sandbox

Workspace: pr-412-sandbox (🧪 Ephemeral)
Created: 17/11/2026, 23:25:00
State file: testform.state.d/pr-412-sandbox/testform.state
Tracked resources: 8
TTL Remaining: 1h 35m

Resources:
  - testcase: testcase/autenticacion.case.feature.@tc-01 (#102)
  - testcase: testcase/autenticacion.case.feature.@tc-02 (#103)
  - testrun:  testruns/smoke_sprint1.run.feature (@tr-01)
```

---

### 5. `testform workspace promote <name>`
**Reconciles and promotes** validated changes from an ephemeral workspace into the official `default` workspace:

```bash
$ testform workspace promote pr-412-sandbox

🚀 Promoting ephemeral workspace "pr-412-sandbox" into default...
✔ 8 resources safely reconciled and merged into Official State.
✨ Workspace "pr-412-sandbox" promoted and cleaned up.
```

This command validates resource integrity, updates the primary `testform.state`, and tears down the ephemeral sandbox.

---

### 6. `testform workspace delete <name>`
Deletes a workspace. If the workspace was created with `-ephemeral`, it automatically triggers a **clean teardown** (`destroy`) on remote providers (Jira/GitHub) before deleting local state:

```bash
$ testform workspace delete pr-412-sandbox
```

**Options:**
- `-a`, `-auto-approve`: Skips interactive confirmation for CI/CD automation.
- `-force`: Forces deletion even if local state is corrupt.

---

## State Isolation in Remote Backends

When using a remote backend (such as AWS S3, Azure Blob, or Google Cloud Storage), Testform stores workspace states under isolated prefixes:
- `default` workspace: `my-bucket/testform.state`
- `staging` workspace: `my-bucket/env:/staging/testform.state`
- `pr-412-sandbox` ephemeral workspace: `my-bucket/env:/pr-412-sandbox/testform.state`

---

## Exit Codes

- `0`: Workspace command completed successfully.
- `1`: Workspace already exists, does not exist, or deletion/promotion failed.
