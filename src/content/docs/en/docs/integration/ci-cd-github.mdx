title: "GitHub Actions Pipeline"
---


Automate test case validation and state reconciliation on every Pull Request and merge to the main production branch.

## Recommended GitOps Lifecycle

1. **Pull Requests:** Executes `testform validate` and `testform plan`. The generated speculative diff is posted directly as a comment on the PR, and a binary plan file is generated.
2. **Merge to Main:** Executes `testform apply tfplan.bin` (or `-auto-approve`) to atomically commit and push approved test specifications to remote platforms.

## Standard Workflow Manifest (.github/workflows/testform.yml)

```yaml
name: Testform CI/CD

on:
  pull_request:
    paths:
      - 'tests/**'
      - 'main.yml'
  push:
    branches:
      - main
    paths:
      - 'tests/**'
      - 'main.yml'

jobs:
  testform:
    name: Testform Plan & Apply
    runs-on: ubuntu-latest

    permissions:
      contents: read
      pull-requests: write

    steps:
      - name: Checkout Repository
        uses: actions/checkout@v4

      - name: Setup Node.js
        uses: actions/setup-node@v4
        with:
          node-version: 20

      - name: Install Dependencies
        run: npm ci

      - name: Validate Syntax & Policies
        run: npx testform validate

      - name: Compute Speculative Plan (Pull Request)
        if: github.event_name == 'pull_request'
        id: plan
        env:
          GITHUB_TOKEN: ${{ secrets.GITHUB_TOKEN }}
        run: |
          npx testform plan -no-color > plan.txt
          echo "PLAN<<EOF" >> $GITHUB_ENV
          cat plan.txt >> $GITHUB_ENV
          echo "EOF" >> $GITHUB_ENV

      - name: Post Plan Comment on PR
        if: github.event_name == 'pull_request'
        uses: actions/github-script@v7
        with:
          github-token: ${{ secrets.GITHUB_TOKEN }}
          script: |
            const planOutput = process.env.PLAN;
            const body = `#### Testform Plan Output \n\`\`\`text\n${planOutput}\n\`\`\``;
            github.rest.issues.createComment({
              issue_number: context.issue.number,
              owner: context.repo.owner,
              repo: context.repo.repo,
              body: body
            });

      - name: Apply Approved Changes (Merge to Main)
        if: github.event_name == 'push' && github.ref == 'refs/heads/main'
        env:
          GITHUB_TOKEN: ${{ secrets.GITHUB_TOKEN }}
        run: npx testform apply -auto-approve
```

## Advanced Binary Plan Pipeline (.github/workflows/testform-plan.yml)

For enterprise pipelines where zero-drift guarantees between reviewed plans and production execution are enforced:

```yaml
name: Testform Speculative Plan & Apply

on:
  pull_request:
    branches: [main]
  push:
    branches: [main]

jobs:
  plan:
    name: Plan Speculative Diff
    runs-on: ubuntu-latest
    if: github.event_name == 'pull_request'
    permissions:
      contents: read
      pull-requests: write
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 20
      - run: npm ci
      - name: Run Testform Plan with Binary Output
        env:
          TESTFORM_GITHUB_TOKEN: ${{ secrets.TESTFORM_GITHUB_TOKEN }}
        run: npx testform plan -out=tfplan.bin -detailed-exitcode || exit_code=$?
      - name: Upload Execution Plan
        uses: actions/upload-artifact@v4
        with:
          name: tfplan
          path: tfplan.bin
          retention-days: 7

  apply:
    name: Apply Approved Plan
    runs-on: ubuntu-latest
    if: github.event_name == 'push' && github.ref == 'refs/heads/main'
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 20
      - run: npm ci
      - name: Apply Direct
        env:
          TESTFORM_GITHUB_TOKEN: ${{ secrets.TESTFORM_GITHUB_TOKEN }}
        run: npx testform apply -auto-approve
```

:::caution[Important: GitHub Actions Token & GitHub Projects V2]
The default token generated automatically by GitHub Actions (`secrets.GITHUB_TOKEN`) has permissions limited to the current repository and **cannot mutate organization or user-level GitHub Projects (Projects V2)** boards.

If your workspace uses `provider: github` synchronized with GitHub Projects:
1. Generate a **Personal Access Token (PAT)** with `repo` and `project` scopes.
2. Store it as a GitHub Secret in your repository (for example, `TESTFORM_GITHUB_TOKEN`).
3. Replace `${{ secrets.GITHUB_TOKEN }}` with `${{ secrets.TESTFORM_GITHUB_TOKEN }}` in the `plan` and `apply` steps.
:::

## Pull Request Workflow with `provider: local`

When a workspace uses `provider: local`, simulated issues are assigned sequential IDs (`local:1`, `local:2`, ...) in `.testform/data.json`, and the reconciled state is recorded in `testform.state`.

If two contributors run `testform apply` on separate branches before opening PRs and commit those JSON files, both branches will allocate colliding IDs and cause **merge conflicts in `testform.state` and `.testform/data.json`**.

To handle Pull Requests cleanly with `provider: local`:

1. **Inside PR branches (before merge):**
   - Only modify `.feature` files, `main.yml`, or `*.vars.yml`.
   - Run `testform validate` and `testform plan` only (read-only operations that never mutate `testform.state` or `data.json`).
   - In the PR workflow, the `plan` step posts the speculative diff for peer review without modifying any JSON state files.
2. **After merging to `main`:**
   - **If versioning state in Git (`backend: local`):** run `testform apply -auto-approve` sequentially on `main` (either manually or in the `push` to `main` CI job committing `testform.state` and `.testform/data.json`, while keeping `data.json` unignored in `.gitignore`).
   - **If running ephemerally:** ignore `testform.state`, `.testform/data.json`, and `.testform/cache/` in `.gitignore`; PRs only track `.feature` + `main.yml`, and CI or local environments rebuild state on demand via `testform apply -auto-approve`.
3. **For teams handling concurrent PRs:** consider switching to `provider: github` (or `gitlab`) with a [remote backend](../language/backends) supporting distributed state locking (S3, GCS, Azure Blob).
