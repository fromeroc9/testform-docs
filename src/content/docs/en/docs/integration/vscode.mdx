The official **Testform DSL for Visual Studio Code** extension (`fromeroc9.testform-dsl`) transforms your editor into a high-performance Integrated Development Environment (IDE) tailored for **Test-as-Code** workflows.

It provides complete Language Server Protocol (LSP) intelligence, multi-layer variable autocompletion, native integration with the VS Code Test Explorer, a full-screen **Specs & Execution Hub** with a retractable export drawer, a unified dual-mode explorer (State & Files), visual state management, speculative plan execution, granular custom field reporting, and bilingual Gherkin formatting.

---

## What's New in Version 1.2.0

- 🧩 **Dynamic Custom Field Detector (`field-detector`):** Real-time workspace scanner that analyzes `main.yml`, `resource.yml`, `testform.state`, and `.feature` files to automatically discover, catalog, and count active project custom fields.
- 🗂️ **Unified Dual-Mode Explorer (State vs. Files):** Seamlessly switch between **State Mode** (`testform.state`) and **Files Mode** (`*.feature`) directly from the top navigation bar of the Explorer view, with instant "Copy Canonical Address" (`testform.state.copyAddress`).
- 📊 **Advanced Reports Explorer with Native Checkboxes:** Granularly select which custom fields to include or omit per report with native VS Code checkboxes, inline output format picker (`xlsx`, `md`, `docx`, `csv`, `json`), and one-click execution.
- 📑 **Specs Hub Export Drawer:** Slide-out export drawer embedded in the Specs Hub Webview featuring report selection, format radio chips, and an interactive checklist of project custom fields with usage count badges.
- 🐛 **Native Bug & Defect Tracking (`.bug.feature`):** First-class support for `@bug` resources, `@bg-X` identity tags, `tf-bug` template snippet, and dedicated `Bugs & Defects` category in State Explorer.
- 🧠 **Context-Aware LSP Scope Detection:** Accurate scope classification (`testcase`, `testrun`, `testplan`, `bug`) enabling strict contextual suggestions for `Rule:` and `Scenario:` targets across 8 configurable insertion formats.
- 🚀 **Google Antigravity IDE & Open VSX Support:** Available on Open VSX Registry and pre-configured for direct 1-click installation/updating in Google Antigravity IDE.

## Pure Standard Language Architecture

Unlike extensions that register proprietary language identifiers and break ecosystem compatibility, Testform v1.0.0 adopts a clean integration model built on open standards:

```text
┌────────────────────────────────────────────────────────────────────────┐
│                   Visual Studio Code Extension Client                  │
│    (Editor decorations, Test Controller, Tree Views, Specs Hub Webview)│
└───────────────────────────────────┬────────────────────────────────────┘
                                    │ JSON-RPC (IPC)
┌───────────────────────────────────▼────────────────────────────────────┐
│                       Testform Language Server                         │
│  ├── Workspace Scanner (Autoloads main.yml, *.vars.yml, .testform/)   │
│  ├── IntelliSense Engine (Variables, locals, data sources, functions)  │
│  ├── Diagnostics Provider (Syntax checks, tag uniqueness, dependencies)│
│  ├── Definition & Hover Provider (F12 / Ctrl+Click jump to definition) │
│  └── Gherkin Formatter (Standard table and keyword indentation)        │
└────────────────────────────────────────────────────────────────────────┘
```

- **Standard Language IDs:** Operates directly on standard `yaml` and `gherkin` file types.
- **Compatibility with Red Hat YAML & Prettier:** Your `main.yml`, `variables.yml`, and `*.vars.yml` manifests are properly formatted and validated by Red Hat YAML or Prettier without syntax warnings.
- **TextMate DSL Injection:** The custom Testform grammar injects semantic highlighting for `${var.*}`, `${local.*}`, `@depends_on` directives, and `* set status` actions directly over standard Gherkin and YAML grammar.

## Language Server Protocol (LSP) Capabilities

The extension runs a dedicated Language Server in the background that continuously monitors your workspace (`main.yml`, `*.vars.yml`, `*.feature`, and the `.testform/` cache directory).

### 1. IntelliSense & Testform DSL Expressions

When authoring `.case.feature`, `.run.feature`, `.plan.feature`, or YAML configuration manifests, the engine provides rich context-aware autocompletions:

- **Input Variables (`${var.*}`):**
  Typing `${var.` displays all variables declared across workspace manifests, showing resolved types (`string`, `number`, `bool`, etc.), default values, and declaration file paths.
- **Computed Local Values (`${local.*}`):**
  Autocompletes computed expressions defined within `locals:` blocks.
- **Data Source Attributes (`${data.*}`):**
  Attribute suggestions for active data sources (`data.http.*`, etc.).
- **Module Outputs (`${module.<name>.<output>}`):**
  Direct access to outputs exported by declared modules.
- **System Environment Variables (`${env.*}`):**
  Access to system environment variables at runtime.
- **Built-in Transformation Functions:**
  Full autocomplete with argument placeholders for all built-in functions:
  - **Strings:** `lower()`, `upper()`, `trim()`, `trimprefix()`, `trimsuffix()`, `startswith()`, `endswith()`, `replace()`, `split()`, `join()`, `format()`, `substr()`.
  - **Collections & Maps:** `contains()`, `coalesce()`, `lookup()`, `length()`, `element()`, `slice()`, `merge()`.
  - **System & Encoding:** `env()`, `uuid()`, `timestamp()`, `jsonencode()`, `jsondecode()`, `file()`.

### 2. Smart Tag Suggestions & Sequence Calculation

- **Automatic Sequential ID Calculation:** Typing `@tc-`, `@tr-`, or `@tp-` prompts the server to scan the workspace and automatically calculate the next available ID (e.g., if `@tc-1` through `@tc-5` exist, it suggests `@tc-6`).
- **Custom Field Enum Suggestions:** Auto-suggests tags declared in `main.yml` (e.g., `@priority:Critical`, `@component:Auth`, `@severity:Blocker`), validating against permitted enum lists.

### 3. Go to Definition (F12) & Hover Cards

- **Jump to Definition (`F12` / `Ctrl+Click`):**
  Click on any `${var.endpoint}` or `${local.auth_token}` reference in a `.feature` file to jump directly to its YAML manifest definition line.
- **Rich Hover Cards:**
  Hover over any variable or local reference to inspect its documentation, data type, default value, and source file path.
- **Dependency Navigation:**
  Navigate cross-file `@depends_on("path/to.case.feature.@tc-1")` directives with instant jump-to-target.

### 4. Real-Time Diagnostics & Quality Gates

The analyzer checks syntax in real-time, underlining potential issues:
- **Undeclared Variables:** Flags references to `${var.missing}` that are not declared in workspace manifests.
- **Dependency Validations (`@depends_on`):**
  - Warns on empty directives: `@depends_on("")`.
  - Catches references to non-existent tags within the same file.
  - Detects broken dependencies pointing to missing target files or tags.
  - Prevents self-referential dependencies (a scenario depending on itself).
- **Duplicate Identity Tags:** Alerts if two scenarios accidentally share the same identity tag (`@tc-1`).
- **Enum Restriction Enforcement:** Warns when custom metadata values don't match allowed enum entries defined in `main.yml`.

## Native Test Explorer (VS Code Test Controller)

Testform connects directly to VS Code's native Testing sidebar:

1. **Automatic Discovery:**
   Scans `.feature` files and builds a visual test hierarchy in the VS Code Testing view.
2. **Gutter Execution Icons:**
   Play buttons appear next to line numbers for each `Scenario` or feature definition.
3. **Interactive Status Selection Prompt:**
   Clicking Play triggers an interactive outcome prompt covering all Cucumber Gherkin statuses (plus QA `blocked`) before recording execution state:
   - `passed`
   - `failed`
   - `pending`
   - `skipped`
   - `undefined`
   - `ambiguous`
   - `blocked`
4. **Real-Time State Synchronization:**
   Watches `testform.state` and dynamically updates tree test statuses (`Passed` in green, `Failed` in red, `Skipped` in gray).

### 1. State & Specifications Explorer (`testform.views.state`)
- **Unified Dual-Mode Explorer:** Switch seamlessly between views with top navigation bar icons (`$(file-code)` / `$(database)`):
  - **State Mode (`testform.state`):** Inspect reconciled resources categorized into `Test Cases`, `Test Runs`, `Test Plans`, `Bugs & Defects`, and `Outputs`. Expand executed test cases with live statuses, examine associated test runs, and view raw JSON attributes.
  - **Files Mode (`*.feature`):** Browse the physical workspace specification hierarchy grouping Gherkin files, scenarios, and metadata tags.
- **Copy Canonical Address:** Context menu and inline action (`$(copy)`) to quickly copy the exact canonical target address (`path/to/feature.@tc-01`) of any test case, suite, or execution to the clipboard.
- **Inspect Resource (JSON):** Open any resource in a temporary editor tab to view its exact JSON representation from `testform.state`.
- **Interactive Taint / Untaint:** Mark resources as `Tainted` (forcing recreation on the next plan/apply cycle) without terminal commands.
- **State Remove (`state rm`):** Remove an item from the state ledger without deleting the specification file on disk.
- **Force Unlock (`force-unlock`):** Release stuck remote or local locks with an interactive Lock ID prompt.

### 2. Modules & .testform View (`testform.views.modules`)
- Inspect remote Git modules declared in `main.yml` and their local copies under `.testform/modules/`.
- Open local governance policy scripts in `.testform/policies/`.
- Audit internal cache state (`.testform/cache/backend.json` and `.testform/cache/lock.json`).

### 3. Reports & Analytics View (`testform.views.reports`)
- **Official & Custom Reports:** Supports all core reports (`testcase-summary`, `testrun-summary`, `testrun-detailed`, `testplan-summary`, `defects`, `traceability`, `coverage`, `two-dimensional`, `test-case-activity`) and dynamically discovers user reports in `.testform/reports/*.ts`.
- **Granular Custom Fields Selection (Native Checkboxes):** Expanding any report node presents an interactive checklist of project custom fields detected by the scanning engine. Select/deselect individual fields with native checkboxes, or use bulk select/deselect actions.
- **Inline Format Selector:** Easily toggle the active output format between **Excel (`.xlsx`)**, **Markdown (`.md`)**, **Word (`.docx`)**, **CSV (`.csv`)**, and **JSON (`.json`)**.
- **One-Click Direct Execution:** Inline Play button to run `testform report <slug> -format=<fmt> --fields="all|none|a,b,c"` in the integrated terminal with zero manual typing.

### 4. State Time Machine View (`testform.views.history`)
- **Git-Powered State History:** Dedicated sidebar tree discovering every Git commit that altered `testform.state`.
- **Snapshot Badges & Metadata:** Shows serial number badges `[#serial]`, author, relative timestamps, and resource breakdown (Cases, Runs, Plans, and Bugs) for each point in time.
- **Virtual Diff with Current Working State:** Double-click any commit or click `$(git-compare)` to launch VS Code's native diff viewer (`vscode.diff`) against your current local state ledger via `testform-state-revision://`.
- **One-Click Safe State Rollback (`$(discard)`):** Revert your working `testform.state` to the exact content of that Git revision after a safe confirmation prompt.

## Visual Plan Diff Webview (`testform.showPlanDiff`)

The extension includes a dedicated, rich Webview panel to inspect speculative execution plans before applying, accessible from any `.feature` editor title bar (`$(diff)`), the Control Center menu, or the Command Palette:

- **Color-Coded Change Inspection:**
  - 🟢 **To Add (`+`)**: New resources detected in your specifications pending ledger creation.
  - 🟡 **To Change (`~`)**: Attribute alterations and cryptographic signature drifts (`localHash`).
  - 🔴 **To Destroy (`-`)**: Resources scheduled for deletion.
  - 🔵 **To Replace (`+/-`)**: Destructive recreation caused by immutable attribute changes.
- **Dynamic Filters & Real-Time Search:** Filter by action type (`All`, `Add`, `Change`, `Destroy`) or search on-the-fly by canonical address, scenario title, or tag.
- **Formatted Gherkin Steps:** Visual step breakdown with highlighted BDD keywords (`Given`, `When`, `Then`, `* set`).
- **Source Code Navigation:** Click any file link to immediately jump to the exact line in the editor.
- **Direct Apply Execution:** One-click green button to execute `testform apply` or `testform apply -auto-approve` without leaving the panel.

## Intelligent Gherkin Formatter

The extension provides a high-performance native formatter:

- **Shortcut:** `Shift+Alt+F` (Windows/Linux) or `Shift+Option+F` (macOS), or via `Testform: Format Document`.
- **Indentation Rules:**
  - Column 0: `Feature:` / `Característica:`
  - 2 Spaces: `Rule:`, `Background:`, `Scenario:`, `Scenario Outline:`, `Examples:`
  - 4 Spaces: Executable steps (`Given`, `When`, `Then`, `And`, `But`, `*` and Spanish equivalents `Dado`, `Cuando`, `Entonces`, `Y`, `Pero`)
  - 6 Spaces: Data tables (`| key | value |`) and DocString blocks (`"""` or ```` ``` ````).
- **Full Bilingual Support:** Formats both English and Spanish Gherkin keywords seamlessly.

## Extension Settings

Customize extension behavior in `.vscode/settings.json`:

```json
{
  // Path to the testform executable binary (default: "testform" from PATH)
  "testform.executablePath": "testform",

  // Enable the Testform Gherkin formatter as the default formatter for .feature files
  "testform.format.enable": true,

  // Enable real-time syntax, variable resolution, and dependency diagnostics
  "testform.diagnostics.enable": true,

  // Enable native VS Code Test Controller integration (Test Explorer & gutter play buttons)
  "testform.testController.enable": true,

  // Trace communication between VS Code and the Testform Language Server
  "testform.trace.server": "off"
}
```

### Recommended Project Settings

To enforce consistent formatting across your QA team, add to `.vscode/settings.json`:

```json
{
  "[gherkin]": {
    "editor.defaultFormatter": "fromeroc9.testform",
    "editor.formatOnSave": true
  },
  "[yaml]": {
    "editor.insertSpaces": true,
    "editor.tabSize": 2
  }
}
```
