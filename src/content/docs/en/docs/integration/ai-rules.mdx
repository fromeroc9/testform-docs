When coding with AI assistants and autonomous coding agents (**Cursor**, **Claude Code**, **Antigravity**, **GitHub Copilot**, or **Windsurf**), the model requires clear directives and architectural constraints to produce 100% valid, drift-free **Test-as-Code** specifications.

Testform provides an authoritative, standardized ruleset ready to drop into your repository root.

## 📐 The 4 Primitives and Strict Contracts

### 1. Test Cases (`*.case.feature`)
* **Feature Header**: Must declare `@testcase` on the `Feature:` line.
* **Feature Tag Restriction**: Arbitrary functional tags (e.g. `@smoke`, `@regression`) on the `Feature:` line are **strictly prohibited**. Only `@testcase` and optionally `@ns(namespace)` are allowed. All functional tags belong on `Scenario:` lines.
* **Sequential Identity**: Every scenario must have a sequential `@tc-*` tag (`@tc-01`, `@tc-02`).
* **Mandatory BDD Steps**: Every scenario **must** contain at least one `Given`, `When`, and `Then` step.
* **Zero `* set`**: Any `* set` step (including `attach`) is **strictly prohibited** in test cases. For contract metadata, declare `* field <name> = <val>`.

### 2. Test Runs (`*.run.feature`)
* **Feature Header**: Must declare `@testrun @tr-01` on the `Feature:` line.
* **Dual Structure Support**: Supports `Rule: <path.case.feature>` (`Scenario: @tc-01`) or direct canonical addresses without Rule (`Scenario: tests/features/login.case.feature.@tc-01`).
* **Background Scope**: Allows suite-level execution marks (`* set duration = "1m 20s"`, `* set attach = "..."`, `* set trace = "..."`). **Declaring `set status` in Background is prohibited** (suite status is autocalculated from scenarios).
* **Scenario Scope**: Strictly declares `* set status = <passed|failed|pending|blocked|skipped|undefined|ambiguous>`.
* **Anti-Pattern**: Do **NOT** use `Given/When/Then` steps in `@testrun` files. Test runs record execution outcomes, not behavioral specifications.

### 3. Master Test Plans (`*.plan.feature`)
* **Feature Header**: Must declare `@testplan @tp-01` on the `Feature:` line.
* **Suite Organization**: Group execution suites using `Rule:` blocks.
* **Attachments**: Allowed strictly in `Background:` (`* set attach = ...`). Plan status is autocalculated via rollup.
* **Integrity**: A single `@testrun` must not be assigned to multiple test plans.

### 4. Bugs and Defects (`*.bug.feature`) — Traceable & Exploratory Modes
* **Feature Header**: Must begin with `@bug` (never put `@adhoc` or free tags on `Feature:` due to `no-feature-tags`).
* **Background Scope**: Optionally declares `* set run = testruns/...run.feature` to link the origin run (may be omitted entirely for **exploratory** bugs).
* **Defect-to-Testcase Traceability & Exploratory Exemption**:
  * Linked under `Rule: <path.case.feature>`: `@bg-01 @depends_on(@tc-01)` (or `@bg-01 @tc-01`).
  * Without `Rule:`: canonical address `@bg-01 @depends_on("path.case.feature.@tc-01")`.
  * For **exploratory / ad-hoc bugs**: tag the `Scenario:` with `@adhoc`, `@exploratory`, or `@independent` (e.g. `@bg-02 @adhoc`) or provide `* set trace` so `bug-target-integrity` does not require `@depends_on`.
* **Scenario Scope**: Unlike `@testrun`/`@testplan`, a `@bug` scenario **allows optional `Given/When/Then/And/But` reproduction steps** alongside `* set status = open | in_progress | resolved | reopened | discarded | duplicate`, `* set attach = ...`, `* set trace = ...`, and `* field <name> = <val>`.

## 📎 Attachment Governance Matrix (`* set attach`)

The `* set attach = "attachments/..."` directive is governed by the `attach-governance` policy:

| Resource | Permitted in `Background:`? | Permitted in `Scenario:`? | Governance Rationale |
|---|:---:|:---:|---|
| **`testcase`** | ❌ **PROHIBITED** | ❌ **PROHIBITED** | `* set` is prohibited in testcases; testcases are pure BDD behavioral specifications. |
| **`testrun`** | ✅ **YES** | ❌ **PROHIBITED** | `Background` for environment logs and run artifacts (`exec.log`). Scenarios declare status only. |
| **`testplan`** | ✅ **YES** | ❌ **PROHIBITED** | Release acceptance criteria and certification documentation are plan-wide. |
| **`bug`** | ❌ **PROHIBITED** | ✅ **YES** | Bug evidence must attach to the specific defect scenario, never global background. |

## 🚫 Common Anti-Patterns for AI Agents to Avoid

1. ❌ **Do not use `* set` in `*.case.feature`**: Testcases never contain `set` steps. Use `* field` for contract governance.
2. ❌ **Do not declare fields with `source: "tag"` in `main.yml` as `* field`**: Fields like `priority` configured with `source: "tag"` must be declared as `@tag` labels (e.g. `@medium`).
3. ❌ **Do not declare `* set status` in the `Background:` of `@testrun`**: Suite status is autocalculated by the engine.
4. ❌ **Do not generate Given/When/Then steps in `@testrun` or `@testplan`**: Those resources use status statements and references.
5. ❌ **Do not place attachments in the `Background:` of `@bug` files**: This triggers a blocking validation error.
6. ❌ **Do not omit Given/When/Then in `*.case.feature`**: Full BDD structure is mandatory.
7. ❌ **Do not duplicate identity numbers**: Always inspect existing tags to compute the next consecutive integer.
