---
title: "depends_on"
---


The `depends_on` meta-argument allows you to explicitly define execution dependencies between test scenarios, ensuring that prerequisites are executed in the correct sequence using a topological **Directed Acyclic Graph (DAG)**.

---

## Gherkin Declaration (`@depends_on`)

Dependencies are declared as tags directly above a `Scenario:`, supporting canonical array brackets (matching Terraform lists) as well as comma-separated targets:

```gherkin
@checkout @e2e
@depends_on(["auth/login.feature.@login_success", "inventory/cart.feature.@add_item"])
Scenario: User completes checkout successfully
  Given shopping cart contains selected products
  When user confirms shipping and billing details
  Then order confirmation receipt is issued
```

You can also write `@depends_on("target1", "target2")` or use multiple separate `@depends_on(...)` tags.

### Unquoted Syntax & Rule-Scoped Targeting

Direct references support unquoted syntax for both local tags and identifiers:

```gherkin
@depends_on(@tc-01)
@depends_on(tc-01)
@depends_on("auth/login.case.feature.@tc-01")
```

---

## Defect $\rightarrow$ Testcase Traceability in `@bug`

In defect specifications (`*.bug.feature`), `@depends_on` links the bug scenario directly to its target test case under an enclosing `Rule:`:

```gherkin
Rule: tests/features/checkout.case.feature

  @bg-01 @depends_on(@tc-01)
  Scenario: Error 500 when processing international credit card payment
    * set status = open
    * set attach = "attachments/bugs/error.png"
    * field severity = @critical
```

The engine automatically resolves the reference against the `@tc-01` scenario inside the `Rule:` file, enabling instant **Go-to-Definition (F12)** and **Hover** previews in VS Code. The shorthand side-by-side syntax `@bg-01 @tc-01` is also fully supported.

> [!CAUTION]
> **Deprecated syntax (`* set target`):** Linking defects via `* set target = ...` or `* set case = ...` steps inside `@bug` scenarios is deprecated. Always declare defect-to-case relationships using `@depends_on(@tc-*)` under an enclosing `Rule: <file.case.feature>` (or `@depends_on("path/file.case.feature.@tc-*")`).

---

## Topological DAG Ordering

During `testform plan` and `testform apply`:
1. Testform builds a Directed Acyclic Graph (**DAG**) of all planned test resources.
2. Applies **Kahn's algorithm** to resolve the exact linear execution sequence.
3. Prerequisite scenarios (`auth/login`) are verified **before** downstream scenarios (`checkout/order`).

---

## Circular Dependency Prevention

If a circular dependency cycle is declared ($A \rightarrow B \rightarrow A$), Testform aborts during static analysis before executing any tests:

```text
[ERROR] Circular dependency detected in DAG:
  auth/login.feature.@login_success -> checkout/order.feature.@checkout -> auth/login.feature.@login_success
```

---

## Visualizing the Graph: `testform graph`

Output the complete dependency DAG in standard Graphviz DOT format:

```bash
testform graph
```
```bash
# Render to image using Graphviz:
testform graph | dot -Tpng -o dependencies.png
```
