The resources module defines how Gherkin scenarios (`Scenario:`) are mapped into canonical attributes (`attributes`), lifecycle hooks (`lifecycle`), and internal state (`state`) for remote test management platforms and APIs (GitHub, GitLab, Jira, TestRail, databases, or custom endpoints).

---

## Function Signatures

```typescript
import { registerResource, ResourceTemplate } from '@fromeroc9/testform@beta';

// Register a new resource type or override an existing template
function registerResource(template: ResourceTemplate): void;
```

---

## Structure of `ResourceTemplate`

A resource definition is cleanly separated into 3 decoupled areas:

```typescript
export interface ResourceTemplate {
  /** Unique resource type name (e.g., 'register-pokemon', 'testcase', 'jira_issue') */
  type: string;

  /**
   * Canonical attributes extracted from the Gherkin scenario.
   * Dispatched directly to the provider's CRUD resource handler (create, update, etc.).
   */
  attributes: 
    | ((scenario: ParserScenario, context?: ResourceContext) => Record<string, any>)
    | Record<string, ((scenario: ParserScenario, context?: ResourceContext) => any) | any>;

  /**
   * Optional lifecycle hooks to orchestrate operations before or after CRUD events.
   */
  lifecycle?: ResourceLifecycleHooks;

  /**
   * Internal attributes persisted directly into the cryptographic state ledger (testform.state)
   * and displayed in `testform plan`. Follows the "Set-First" principle: root level contains only
   * runtime execution marks (`* set`) while contract fields live inside `metadata = { ... }`.
   */
  state?: Record<string, ((scenario: ParserScenario, context?: ResourceContext) => any) | any>;

  /** Optional list of flat fields or overrides. */
  fields?: ResourceField[];
}
```

## Core Types: `ParserScenario` and `ResourceContext`

To ensure robust, strongly-typed development with full IDE IntelliSense support, `ResourceTemplate` evaluators receive formal TypeScript interfaces:

### 1. `ParserScenario` (`scenario` or `s`)
Represents the parsed Gherkin scenario extracted by the Testform AST:

| Property | Type | Description |
| :--- | :--- | :--- |
| `name` | `string` | Scenario title (`Scenario: Validate error...`). |
| `steps` | `ParserStep[]` | Ordered list of steps (`keyword`, `text`). |
| `tags` | `string[]` | Tags assigned to the scenario (`['@tc-01', '@smoke']`). |
| `feature` | `ParserFeature` | Parent Feature metadata (`name`, `tags`, `description`). |
| `rule` | `ParserRule?` | Containing `Rule:` block if grouped within a rule. |
| `uri` | `string` | Path to the `.feature` file on disk. |
| `location` | `number` | Line number where the scenario starts. |
| `custom` | `object` | Container for parsed domain metadata: |
| `custom.fields` | `Record<string, string>` | Contractual metadata fields (`project`, `priority`, etc.). |
| `custom.explicitFields` | `Record<string, any>` | Fields written explicitly by hand in the scenario (to detect manual overrides). |
| `custom.set` | `Record<string, any>` | Runtime execution marks (`status`, `attach`, `trace`, `run`). |
| `custom.groupScenarios`| `ParserScenario[]` | In a `testrun`, list of child testcases evaluated. |
| `custom.testruns` | `string[]` | In a `testplan`, list of grouped testrun file paths. |

### 2. `ResourceContext` (`context`)
Provides access to Testform runtime engine services:

| Property | Type | Description |
| :--- | :--- | :--- |
| `config` | `ConfigManager` | Active `main.yml` configuration (resolves category status mappings). |
| `state` | `State` | State ledger manager, allows cross-resource lookups (e.g. testruns in testplan rollup). |
| `testDirectory`| `string` | Root path of the test workspace. |
| `provider` | `string` | Active provider identifier (`github`, `gitlab`, `local`). |
| `variables` | `Record<string, any>` | Resolved local and environment variables. |

## Lifecycle Hooks: `ResourceLifecycleHooks`

Lifecycle hooks enable pre-validation, token acquisition, and seamless orchestration of arbitrary custom provider methods with access to the live `provider` instance:

```typescript
export interface ResourceLifecycleHooks {
  /** Runs before resource creation (pre-validation, external locks, token acquisition). */
  beforeCreate?(args: { attributes: any; scenario: ParserScenario; context: any }): Promise<void> | void;

  /**
   * Runs immediately after the resource is created by the provider.
   * Injects the assigned remote ID and the live provider instance to call custom methods (e.g., photo upload).
   */
  afterCreate?(args: { id: string | number; attributes: any; provider: any; scenario: ParserScenario; context: any }): Promise<void> | void;

  /** Runs before modifying an existing resource. */
  beforeUpdate?(args: { id: string | number; attributes: any; provider: any; scenario: ParserScenario; context: any }): Promise<void> | void;

  /** Runs after modifying the resource. */
  afterUpdate?(args: { id: string | number; attributes: any; diff?: any; provider: any; scenario: ParserScenario; context: any }): Promise<void> | void;

  /** Runs before destroying the resource. */
  beforeDelete?(args: { id: string | number; provider: any; context: any }): Promise<void> | void;

  /** Runs after destroying the resource. */
  afterDelete?(args: { id: string | number; provider: any; context: any }): Promise<void> | void;
}
```

## Full Example: Custom Resource (`register-pokemon`)

Consider registering Pokémon into a **Pokédex**, including uploading the official photo via a custom method exposed on the provider:

```typescript
// .testform/resources/pokemon.ts
import { registerResource } from '@fromeroc9/testform@beta';

export default {
  type: 'register-pokemon',

  // 1. Canonical attributes extracted from the Gherkin scenario
  attributes: (scenario, context) => ({
    nombre: scenario.name,
    tipo: scenario.custom?.fields?.tipo ?? 'Eléctrico',
    nivel: scenario.custom?.fields?.nivel ?? 25,
    foto: scenario.custom?.fields?.foto ?? 'https://img.pokemondb.net/sprites/home/normal/pikachu.png',
  }),

  // 2. Lifecycle orchestration & custom provider function execution
  lifecycle: {
    beforeCreate: async ({ attributes }) => {
      if (attributes.nivel < 1 || attributes.nivel > 100) {
        throw new Error(`Invalid Pokémon level: ${attributes.nivel}. Must be between 1 and 100.`);
      }
    },
    afterCreate: async ({ id, attributes, provider }) => {
      // Injects the live provider instance to call custom actions directly
      if (provider.subirFotoPokemon) {
        await provider.subirFotoPokemon(id, attributes.foto);
      }
    }
  },

  // 3. Internal state persisted in the cryptographic state ledger
  state: {
    region: () => 'Kanto',
    registeredAt: () => new Date().toISOString()
  }
};
```

You can generate a complete resource template inside `.testform/resources/` directly by running:
```bash
testform providers resource scaffold <name>
```

## Overriding Existing Resources

You can override any canonical resource (such as `testcase`) to customize extracted attributes or append lifecycle hooks:

```typescript
// .testform/resources/custom-testcase.ts
import { registerResource } from '@fromeroc9/testform@beta';

registerResource({
  type: 'testcase',
  attributes: (scenario) => ({
    title: `[QA] ${scenario.name}`,
    body: '```gherkin\n' + scenario.steps.map(s => `${s.keyword}${s.text}`).join('\n') + '\n```',
    labels: [...(scenario.tags || []), 'automated'],
  }),
  lifecycle: {
    afterCreate: async ({ id, provider }) => {
      console.log(`Testcase #${id} successfully synchronized with ${provider.name}`);
    }
  }
});
```

## Runtime Inspection (`resource`)

The `resource` registry singleton enables inspecting and evaluating loaded templates at runtime:

```typescript
import { resource } from '@fromeroc9/testform@beta';

// Inspect all registered types
const types = resource.getRegisteredTypes();
// ['testcase', 'testrun', 'testplan', 'bug', 'register-pokemon', ...]

// Evaluate canonical attributes
const attrs = resource.evaluateAttributes('register-pokemon', scenario);

// Retrieve lifecycle hooks
const lifecycle = resource.getLifecycle('register-pokemon');
```
