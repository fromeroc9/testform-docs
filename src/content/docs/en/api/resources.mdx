The resources module defines how Gherkin scenarios (`Scenario:`) are mapped into canonical attributes (`attributes`), lifecycle hooks (`lifecycle`), and internal state (`state`) for remote test management platforms and APIs (GitHub, GitLab, Jira, TestRail, databases, or custom endpoints).

---

## Function Signatures

```typescript
import { registerResource, ResourceTemplate } from '@fromeroc9/testform@beta';

// Register a new resource type or override an existing template
function registerResource(template: ResourceTemplate): void;
```

---

## Structure of `ResourceTemplate`

A resource definition is cleanly separated into 3 decoupled areas:

```typescript
export interface ResourceTemplate {
  /** Unique resource type name (e.g., 'github_testcase', 'metergol', 'jira_issue') */
  type: string;

  /**
   * Canonical attributes extracted from the Gherkin scenario.
   * Dispatched directly to the provider's REST resource handler (post, patch, etc.).
   */
  attributes?: 
    | ((scenario: ParserScenario, context?: any) => Record<string, any>)
    | Record<string, ((scenario: ParserScenario, context?: any) => any) | any>;

  /**
   * Optional lifecycle hooks to orchestrate operations before or after CRUD events.
   */
  lifecycle?: ResourceLifecycleHooks;

  /**
   * Internal attributes persisted directly into the cryptographic state ledger (testform.state).
   */
  state?: Record<string, ((scenario: ParserScenario, context?: any) => any) | any>;

  /** @deprecated Legacy dictionary mapping to provider.apis. Prefer attributes. */
  api?: ResourceApiDefinition;

  /** @deprecated Legacy list of flat fields. */
  fields?: ResourceField[];
}
```

## Lifecycle Hooks: `ResourceLifecycleHooks`

Lifecycle hooks enable pre-validation, token acquisition, and seamless orchestration of arbitrary custom provider methods:

```typescript
export interface ResourceLifecycleHooks {
  /** Runs before resource creation (pre-validation, external locks, token acquisition). */
  beforeCreate?(args: { attributes: any; scenario: ParserScenario; context: any }): Promise<void> | void;

  /**
   * Runs immediately after the resource is created by the provider.
   * Injects the assigned remote ID and the live provider instance to call custom methods.
   */
  afterCreate?(args: { id: string | number; attributes: any; provider: any; scenario: ParserScenario; context: any }): Promise<void> | void;

  /** Runs before modifying an existing resource. */
  beforeUpdate?(args: { id: string | number; attributes: any; provider: any; scenario: ParserScenario; context: any }): Promise<void> | void;

  /** Runs after modifying the resource. */
  afterUpdate?(args: { id: string | number; attributes: any; diff?: any; provider: any; scenario: ParserScenario; context: any }): Promise<void> | void;

  /** Runs before destroying the resource. */
  beforeDelete?(args: { id: string | number; provider: any; context: any }): Promise<void> | void;

  /** Runs after destroying the resource. */
  afterDelete?(args: { id: string | number; provider: any; context: any }): Promise<void> | void;
}
```

## Full Example: Custom Resource (`metergol`)

Consider a domain resource decoupled from issues or tickets, such as `metergol` (recording sports goals into a database and triggering video uploads via provider methods):

```typescript
// .testform/resources/metergol.ts
import { registerResource } from '@fromeroc9/testform@beta';

export default {
  type: 'metergol',

  // 1. Attributes extracted from Gherkin scenario
  attributes: (scenario, context) => ({
    jugador: scenario.name,
    minuto: scenario.custom?.fields?.minuto ?? 45,
    equipo: scenario.custom?.fields?.equipo ?? 'Real Madrid',
    esPenal: scenario.custom?.fields?.esPenal ?? false,
  }),

  // 2. Lifecycle orchestration & custom provider function execution
  lifecycle: {
    beforeCreate: async ({ attributes }) => {
      if (attributes.minuto < 0 || attributes.minuto > 120) {
        throw new Error(`Invalid minute: ${attributes.minuto}`);
      }
    },
    afterCreate: async ({ id, attributes, provider }) => {
      // Injects the live provider instance to call custom actions directly
      if (provider.subirVideoGol) {
        await provider.subirVideoGol(id, attributes.jugador);
      }
    }
  },

  // 3. Internal state persisted in the cryptographic state ledger
  state: {
    partidoId: () => 'final-champions-2026',
    registeredAt: () => new Date().toISOString()
  }
};
```

## Overriding Existing Resources

You can override any built-in resource (such as `github_testcase`) to customize extracted attributes or append lifecycle hooks:

```typescript
// .testform/resources/custom-testcase.ts
import { registerResource } from '@fromeroc9/testform@beta';

registerResource({
  type: 'github_testcase',
  attributes: (scenario) => ({
    title: `[QA] ${scenario.name}`,
    body: '```gherkin\n' + scenario.steps.map(s => `${s.keyword}${s.text}`).join('\n') + '\n```',
    labels: [...(scenario.tags || []), 'automated'],
  }),
  lifecycle: {
    afterCreate: async ({ id, provider }) => {
      console.log(`Testcase #${id} successfully synchronized with provider`);
    }
  }
});
```

## Runtime Inspection (`resource`)

The `resource` registry singleton enables inspecting and evaluating loaded templates at runtime:

```typescript
import { resource } from '@fromeroc9/testform@beta';

// Inspect all registered types
const types = resource.getRegisteredTypes();
// ['github_testcase', 'github_testrun', 'testcase', 'metergol', ...]

// Evaluate canonical attributes
const attrs = resource.evaluateAttributes('metergol', scenario);

// Retrieve lifecycle hooks
const lifecycle = resource.getLifecycle('metergol');
```
