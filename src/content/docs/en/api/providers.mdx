title: "Providers: IProvider Interface"
description: "Programmatic API reference for authoring custom provider adapters in Testform."
---

Providers in Testform are adapters that translate declarative test synchronization intentions into remote platforms (GitHub, GitLab, Jira, Zephyr, TestRail, REST microservices, or custom APIs like a Pokédex).

Any custom provider must satisfy the `IProvider` interface contract.

---

## 1. The `IProvider` Interface Contract

The `IProvider` interface is **100% pure and agnostic**: it does not enforce ticket or issue concepts or hardcoded platform methods. All transport and persistence behavior is delegated to its resource bus (`resources`):

```typescript
export interface IProvider {
  name?: string;

  /**
   * Formats the human-readable remote identifier shown in terminal output and state ledger (.testform/state.json).
   * Examples: '#105' (GitHub), 'GL#105' (GitLab), 'QA-402' (Jira), 'PK#25' (Pokedex), 'local:1'.
   */
  formatRemoteId(id: number | string): string;

  /**
   * Map of resources managed by this provider (e.g., { 'register-pokemon', issue, testrun, defect }).
   * Each handler exposes standard CRUD lifecycle methods (create, read, update, delete), REST aliases, and custom functions.
   */
  resources: Record<string, IProviderResourceHandler>;

  /**
   * Optional alias for `resources`.
   */
  apis?: Record<string, IProviderResourceHandler>;

  /**
   * Arbitrary custom provider functions, SDK clients, and helper methods (e.g., subirFotoPokemon()).
   */
  [customProperty: string]: any;
}
```

## 2. Resource Handler: `IProviderResourceHandler`

To handle any arbitrary domain entity or API (without being forced into issue semantics), the provider defines resource handlers exposing standard CRUD lifecycle methods (matching Terraform parity), REST aliases, and custom RPC methods:

```typescript
export interface IProviderResourceHandler<TAttrs = any, TResult = any> {
  // ─── Standard CRUD Lifecycle Methods (Primary Standard / Terraform Parity) ───
  create?(attributes: TAttrs, context?: any): Promise<TResult>;
  read?(id: string | number, context?: any): Promise<TResult | null>;
  update?(id: string | number, attributes: Partial<TAttrs>, context?: any): Promise<TResult>;
  delete?(id: string | number, context?: any): Promise<void>;

  // ─── Optional REST Aliases ───
  post?(attributes: TAttrs, context?: any): Promise<TResult>;
  get?(id: string | number, context?: any): Promise<TResult | null>;
  patch?(id: string | number, attributes: Partial<TAttrs>, context?: any): Promise<TResult>;
  put?(id: string | number, attributes: TAttrs, context?: any): Promise<TResult>;

  // ─── Arbitrary Custom Actions & RPC Methods ───
  [customAction: string]: ((...args: any[]) => Promise<any>) | undefined;
}
```

## 3. Full Example: Pokédex Provider (`register-pokemon` with Photo)

Below is an agnostic provider that implements the `register-pokemon` resource with standard CRUD methods and a custom `subirFotoPokemon` method:

```typescript
// ./custom-providers/pokedex-provider.ts
import { IProvider, IProviderResourceHandler } from '@fromeroc9/testform@beta';

export default class PokedexProvider implements IProvider {
  public name = 'pokedex';

  // 1. Agnostic resource handler for 'register-pokemon'
  public resources: Record<string, IProviderResourceHandler> = {
    'register-pokemon': {
      create: async (attrs: any, context?: any) => {
        const res = await fetch('https://pokeapi.co/api/v2/pokemon', {
          method: 'POST',
          headers: { 'Content-Type': 'application/json' },
          body: JSON.stringify(attrs)
        });
        const data = await res.json();
        return { id: data.id, number: data.id };
      },
      read: async (id: number | string) => {
        const res = await fetch(`https://pokeapi.co/api/v2/pokemon/${id}`);
        return res.ok ? await res.json() : null;
      },
      update: async (id: number | string, attrs: any) => {
        const res = await fetch(`https://pokeapi.co/api/v2/pokemon/${id}`, {
          method: 'PUT',
          headers: { 'Content-Type': 'application/json' },
          body: JSON.stringify(attrs)
        });
        return await res.json();
      },
      delete: async (id: number | string) => {
        await fetch(`https://pokeapi.co/api/v2/pokemon/${id}`, { method: 'DELETE' });
      }
    }
  };

  // 2. Custom method called directly from Resource.lifecycle.afterCreate
  public async subirFotoPokemon(pokemonId: string | number, fotoUrl: string): Promise<void> {
    console.log(`Uploading photo for Pokémon #${pokemonId} from ${fotoUrl}...`);
    // S3 upload or asset storage call
  }

  formatRemoteId(id: number | string): string {
    return `PK#${id}`;
  }
}
```

## 4. Multi-Resource Providers

When a provider manages different types of entities (e.g., test cases `issue`, test runs `testrun`, or defects `defect`), each resource is declared as an independent handler inside the `resources` object:

```typescript
// ./custom-providers/jira.ts
import { IProvider, IProviderResourceHandler } from '@fromeroc9/testform@beta';

export default class JiraProvider implements IProvider {
  public name = 'jira';

  public resources: Record<string, IProviderResourceHandler> = {
    // 1. Handler for test cases / issues
    issue: {
      create: async (attrs: any) => {
        const res = await fetch(`https://company.atlassian.net/rest/api/3/issue`, {
          method: 'POST',
          headers: { 'Authorization': `Bearer ${process.env.JIRA_TOKEN}`, 'Content-Type': 'application/json' },
          body: JSON.stringify({ fields: { summary: attrs.title, description: attrs.body } })
        });
        const data = await res.json();
        return { id: data.id, number: parseInt(data.key.split('-')[1], 10), title: attrs.title, state: 'open' };
      },
      read: async (id: number | string) => {
        const res = await fetch(`https://company.atlassian.net/rest/api/3/issue/${id}`);
        return res.ok ? await res.json() : null;
      },
      update: async (id: number | string, attrs: any) => {
        const res = await fetch(`https://company.atlassian.net/rest/api/3/issue/${id}`, {
          method: 'PUT',
          headers: { 'Content-Type': 'application/json' },
          body: JSON.stringify(attrs)
        });
        return await res.json();
      },
      delete: async (id: number | string) => {
        await fetch(`https://company.atlassian.net/rest/api/3/issue/${id}`, { method: 'DELETE' });
      }
    },

    // 2. Handler for test executions (Test Runs)
    testrun: {
      create: async (attrs: any) => {
        // Persistence logic in Jira / Xray / Zephyr
        return { id: `TR-${Date.now()}`, number: 1 };
      },
      read: async (id: number | string) => {
        return null;
      },
      update: async (id: number | string, attrs: any) => {
        return { id, number: Number(id) };
      },
      delete: async (id: number | string) => {
        // Deletion in Jira / Xray
      }
    }
  };

  formatRemoteId(id: number | string): string {
    return `JIRA-${id}`;
  }
}
```

## 5. Declaration in `main.yml`

With strict Terraform parity, providers must be declared in `testform.required_providers`:

```yaml
testform:
  required_version: ">= 1.0.0"
  required_providers:
    pokedex: "./custom-providers/pokedex-provider.ts"
    jira: "git::https://gitlab.company.com/qa/providers.git//jira.ts?ref=v1.2.0"

provider:
  pokedex:
    api_url: "https://pokeapi.co/api/v2"
```

## 6. Scaffolding with the CLI (`testform providers scaffold`)

To generate a new provider template preconfigured with CRUD methods:

```bash
# 1. Single TypeScript file:
testform providers scaffold pokedex

# 2. Complete Git/npm project with Vitest and TypeScript:
testform providers scaffold pokedex --project
```
