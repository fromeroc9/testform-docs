description: "Referencia de la API programática para desarrollar adaptadores de integración de proveedores en Testform."
---

Los proveedores (*Providers*) en Testform son adaptadores que traducen las intenciones de sincronización de pruebas declarativas hacia plataformas remotas (GitHub, GitLab, Jira, Zephyr, TestRail, microservicios REST o APIs propietarias como una Pokédex).

Cualquier proveedor personalizado debe satisfacer el contrato de interfaz `IProvider`.

---

## 1. Contrato de la Interfaz `IProvider`

La interfaz `IProvider` es **100% pura y agnóstica**: no impone conceptos de tickets, issues ni métodos predeterminados de plataformas específicas. Todo el comportamiento de transporte y persistencia se delega en su bus de recursos (`resources`):

```typescript
export interface IProvider {
  name?: string;

  /**
   * Formatea el identificador remoto mostrado en la consola y el ledger de estado (.testform/state.json).
   * Ejemplos: '#105' (GitHub), 'GL#105' (GitLab), 'QA-402' (Jira), 'PK#25' (Pokedex), 'local:1'.
   */
  formatRemoteId(id: number | string): string;

  /**
   * Mapa de recursos gestionados por este proveedor (ej. { 'register-pokemon', issue, testrun, defect }).
   * Cada manejador expone el ciclo de vida CRUD estándar (create, read, update, delete), alias REST y funciones custom.
   */
  resources: Record<string, IProviderResourceHandler>;

  /**
   * Alias opcional para `resources`.
   */
  apis?: Record<string, IProviderResourceHandler>;

  /**
   * Funciones custom arbitrarias, clientes SDK y métodos auxiliares (ej. subirFotoPokemon()).
   */
  [customProperty: string]: any;
}
```

---

## 2. Manejador de Recursos: `IProviderResourceHandler`

Para soportar cualquier tipo de entidad o API agnóstica (sin forzar conceptos de issues), el proveedor define manejadores con métodos CRUD estándar (paridad con Terraform), alias REST y métodos RPC custom:

```typescript
export interface IProviderResourceHandler<TAttrs = any, TResult = any> {
  // ─── Métodos del Ciclo de Vida CRUD (Estándar Principal / Terraform Parity) ───
  create?(attributes: TAttrs, context?: any): Promise<TResult>;
  read?(id: string | number, context?: any): Promise<TResult | null>;
  update?(id: string | number, attributes: Partial<TAttrs>, context?: any): Promise<TResult>;
  delete?(id: string | number, context?: any): Promise<void>;

  // ─── Alias Opcionales para Providers REST Puros ───
  post?(attributes: TAttrs, context?: any): Promise<TResult>;
  get?(id: string | number, context?: any): Promise<TResult | null>;
  patch?(id: string | number, attributes: Partial<TAttrs>, context?: any): Promise<TResult>;
  put?(id: string | number, attributes: TAttrs, context?: any): Promise<TResult>;

  // ─── Acciones y Funciones Personalizadas Arbitrarias ───
  [customAction: string]: ((...args: any[]) => Promise<any>) | undefined;
}
```

## 3. Ejemplo Completo: Proveedor Pokédex (`register-pokemon` con Foto)

A continuación se muestra un proveedor agnóstico que implementa el recurso `register-pokemon` con métodos CRUD y una función custom `subirFotoPokemon`:

```typescript
// ./custom-providers/pokedex-provider.ts
import { IProvider, IProviderResourceHandler } from '@fromeroc9/testform@beta';

export default class PokedexProvider implements IProvider {
  public name = 'pokedex';

  // 1. Manejador del recurso agnóstico 'register-pokemon'
  public resources: Record<string, IProviderResourceHandler> = {
    'register-pokemon': {
      create: async (attrs: any, context?: any) => {
        const res = await fetch('https://pokeapi.co/api/v2/pokemon', {
          method: 'POST',
          headers: { 'Content-Type': 'application/json' },
          body: JSON.stringify(attrs)
        });
        const data = await res.json();
        return { id: data.id, number: data.id };
      },
      read: async (id: number | string) => {
        const res = await fetch(`https://pokeapi.co/api/v2/pokemon/${id}`);
        return res.ok ? await res.json() : null;
      },
      update: async (id: number | string, attrs: any) => {
        const res = await fetch(`https://pokeapi.co/api/v2/pokemon/${id}`, {
          method: 'PUT',
          headers: { 'Content-Type': 'application/json' },
          body: JSON.stringify(attrs)
        });
        return await res.json();
      },
      delete: async (id: number | string) => {
        await fetch(`https://pokeapi.co/api/v2/pokemon/${id}`, { method: 'DELETE' });
      }
    }
  };

  // 2. Función personalizada expuesta para ser invocada desde Resource.lifecycle
  public async subirFotoPokemon(pokemonId: string | number, fotoUrl: string): Promise<void> {
    console.log(`Subiendo foto del Pokémon #${pokemonId} desde ${fotoUrl}...`);
    // Almacenamiento en S3 o servicio multimedia
  }

  formatRemoteId(id: number | string): string {
    return `PK#${id}`;
  }
}
```

## 4. Proveedores Multi-Recurso (Manejo de Múltiples Recursos)

Cuando un proveedor soporta diferentes tipos de entidades (por ejemplo, incidencias `issue`, ejecuciones de pruebas `testrun` o defectos `defect`), cada una se declara como un manejador independiente dentro del objeto `resources`:

```typescript
// ./custom-providers/jira.ts
import { IProvider, IProviderResourceHandler } from '@fromeroc9/testform@beta';

export default class JiraProvider implements IProvider {
  public name = 'jira';

  public resources: Record<string, IProviderResourceHandler> = {
    // 1. Manejador para casos de prueba / incidencias
    issue: {
      create: async (attrs: any) => {
        const res = await fetch(`https://empresa.atlassian.net/rest/api/3/issue`, {
          method: 'POST',
          headers: { 'Authorization': `Bearer ${process.env.JIRA_TOKEN}`, 'Content-Type': 'application/json' },
          body: JSON.stringify({ fields: { summary: attrs.title, description: attrs.body } })
        });
        const data = await res.json();
        return { id: data.id, number: parseInt(data.key.split('-')[1], 10), title: attrs.title, state: 'open' };
      },
      read: async (id: number | string) => {
        const res = await fetch(`https://empresa.atlassian.net/rest/api/3/issue/${id}`);
        return res.ok ? await res.json() : null;
      },
      update: async (id: number | string, attrs: any) => {
        const res = await fetch(`https://empresa.atlassian.net/rest/api/3/issue/${id}`, {
          method: 'PUT',
          headers: { 'Content-Type': 'application/json' },
          body: JSON.stringify(attrs)
        });
        return await res.json();
      },
      delete: async (id: number | string) => {
        await fetch(`https://empresa.atlassian.net/rest/api/3/issue/${id}`, { method: 'DELETE' });
      }
    },

    // 2. Manejador para ejecuciones de prueba (Test Runs)
    testrun: {
      create: async (attrs: any) => {
        // Lógica de persistencia en Jira / Xray / Zephyr
        return { id: `TR-${Date.now()}`, number: 1 };
      },
      read: async (id: number | string) => {
        return null;
      },
      update: async (id: number | string, attrs: any) => {
        return { id, number: Number(id) };
      },
      delete: async (id: number | string) => {
        // Eliminación en Jira / Xray
      }
    }
  };

  formatRemoteId(id: number | string): string {
    return `JIRA-${id}`;
  }
}
```

## 5. Declaración en `main.yml`

Con paridad estricta a Terraform, los proveedores deben declararse en `testform.required_providers`:

```yaml
testform:
  required_version: ">= 1.0.0"
  required_providers:
    pokedex: "./custom-providers/pokedex-provider.ts"
    jira: "git::https://gitlab.empresa.com/qa/providers.git//jira.ts?ref=v1.2.0"

provider:
  pokedex:
    api_url: "https://pokeapi.co/api/v2"
```

## 6. Generación con la CLI (`testform providers scaffold`)

Para crear la plantilla de un nuevo proveedor con métodos CRUD pre-configurados:

```bash
# 1. Archivo único en TypeScript:
testform providers scaffold pokedex

# 2. Proyecto completo listo para Git / npm con Vitest y TypeScript:
testform providers scaffold pokedex --project
```
