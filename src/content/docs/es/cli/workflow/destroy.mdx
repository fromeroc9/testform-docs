---
title: "testform destroy"
---

```bash
testform [opciones globales] destroy [opciones]
```

El comando `testform destroy` elimina de forma permanente (o realiza *fallback* a cierre + desvinculación de GitHub Projects V2 cuando los permisos del repositorio restringen el borrado) todos los recursos remotos registrados en el archivo de estado para el alcance indicado, sin borrar tus archivos locales `.feature`.

## Opciones del Comando

| Opción | Por Defecto | Descripción |
| :--- | :--- | :--- |
| `--auto-approve`, `-a` | `false` | Omite la confirmación interactiva antes de proceder a la destrucción. |
| `--target=<address>` | — | Limita la destrucción a una instancia o alcance específico (ej.: `login.case.feature.@tc-1`). |
| `--parallelism=<n>` | `1` | Límite de eliminaciones remotas concurrentes por lote. |
| `--lock=false` | `true` | Desactiva el bloqueo de estado durante la destrucción. |
| `--lock-timeout=<dur>` | `0s` | Tiempo máximo de espera para adquirir el bloqueo de estado. |
| `--input=false` | `true` | Deshabilita prompts interactivos (útil en CI/CD). |
| `--no-color` | `false` | Desactiva los colores en la salida. |

## Ejemplo de Ejecución Real

```bash
$ testform destroy --target=testcase
...

Do you really want to destroy these resources?
  Testform will destroy the tracked remote resources shown above.
  There is no undo. Only 'yes' will be accepted to confirm.

  Enter a value: yes

github.testcase.login.case.feature.@tc-1: Destruction complete after 2s [id=testform-demo:104]

```

## Destrucción Paralela y Dirigida

Para acelerar limpiezas masivas de múltiples issues:

```bash
testform destroy --auto-approve --parallelism 5
```

Para destruir un escenario aislado sin perjudicar al resto de la suite de pruebas:

```bash
testform destroy --target="auth.case.feature.@tc-2"
```

> **Comportamiento por Proveedor (`github`, `gitlab`, `local`):** `GitHubProvider` utiliza la mutación GraphQL `deleteIssue` para eliminar permanentemente el issue del repositorio y del GitHub Project V2 asociado, `GitLabProvider` llama a `DELETE /projects/:id/issues/:issue_iid`, y `LocalProvider` elimina el registro de `.testform/data.json` (limpiando además referencias huérfanas en `sub_issues`). Los issues inexistentes (`404`/`410`) se tratan de forma idempotente, las respuestas transitorias `5xx` en GitHub se reintentan automáticamente, y si los permisos del repositorio/proyecto restringen el borrado (por ejemplo, roles que no son Owner en GitLab), Testform hace *fallback* cerrando el issue (y quitando el ítem de Project V2 en GitHub).

## Códigos de Salida

- `0`: Todos los recursos seleccionados se destruyeron satisfactoriamente.
- `1`: Ocurrió un error durante la destrucción.
