---
title: "testform providers"
description: "Muestra el árbol de requisitos de proveedores, bloquea versiones (.testform/cache/lock.json), genera mirrors y expone esquemas de recursos."
---

```bash
testform [opciones globales] providers [subcomando] [opciones] [DIR]
```

El comando `testform providers` analiza la configuración del módulo referenciado y muestra un árbol de requisitos de proveedores (`providers`) necesarios para la ejecución. También incluye subcomandos para bloquear dependencias (`lock`), duplicar plugins en entornos air-gapped (`mirror`) y exportar esquemas formales en JSON (`schema`).

Si se ejecuta en un directorio sin archivos de configuración (`main.yml`, etc.), emite un diagnóstico idéntico a Terraform y sale con código 1:

```text
╷
│ Error: No configuration files
│
│ The directory C:\Users\flavi\Desktop\auth contains no Testform configuration files.
╵
```

---

## Subcomandos

### 1. Árbol de Proveedores (por defecto)

```bash
testform providers [DIR]
```

Muestra los proveedores requeridos por la configuración activa:

```bash
$ testform providers

Providers required by configuration:
.
└── provider[registry.testform.io/fromeroc9/local] 1.0.0
```

### 2. `testform providers lock`

```bash
testform providers lock [opciones] [providers...]
```

Normalmente el archivo de lock (`.testform/cache/lock.json`) se actualiza durante `testform init`. El subcomando `lock` permite auditar y actualizar de forma explícita los hashes de integridad criptográfica y compatibilidad multiplataforma en `.testform/cache/lock.json`, asegurando builds reproducibles e inmutables en CI/CD:

```bash
$ testform providers lock

Success! Dependencies for provider "fromeroc9/github" verified and written to .testform/cache/lock.json.
```

#### Opciones de `lock`:

| Opción | Descripción |
| :--- | :--- |
| `-platform=os_arch` | Solicita checksums para una plataforma específica (ej. `linux_amd64`, `windows_amd64`, `darwin_arm64`). Puede repetirse. |
| `-fs-mirror=dir` | Consulta un directorio local de mirrors en lugar del registry oficial. |
| `-net-mirror=url` | Consulta un mirror de red (URL base) en lugar del registry oficial. |
| `-enable-plugin-cache` | Habilita el uso de la caché global de plugins para acelerar el bloqueo. |
| `-test-directory=path` | Directorio de pruebas de Testform (por defecto `tests`). |
| `-var 'foo=bar'` | Define una variable de configuración en el módulo raíz. |
| `-var-file=filename` | Carga variables desde un archivo (`testform.vars.yml` o `*.auto.vars.yml`). |

### 3. `testform providers mirror`

```bash
testform providers mirror [opciones] <target-dir>
```

Popula un directorio local con copias de los plugins de proveedores requeridos por la configuración actual. Este directorio puede usarse directamente como un mirror del sistema de archivos o como base para un servidor web estático privado (red mirror), permitiendo ejecuciones de Testform en entornos empresariales **air-gapped** o sin conexión a internet:

```bash
$ testform providers mirror ./vendor-plugins
- Mirroring provider "fromeroc9/github" to ./vendor-plugins...

Success! Provider plugins mirrored to ./vendor-plugins.
```

> [!NOTE]
> El argumento `<target-dir>` es obligatorio. Si se omite, Testform emitirá un error indicando `Missing target directory argument`.

### 4. `testform providers schema`

```bash
testform providers schema [opciones]
```

Inspecciona la definición formal del esquema (atributos, tipos de datos y obligatoriedad de `testcase`, `testrun`, `testplan`) provisto por el proveedor activo.

#### Modo Legible:
```bash
$ testform providers schema

Provider Schema: fromeroc9/github
──────────────────────────────────────────────────
Resource: github_testcase
  - identity: string (required)
  - title: string (optional)
  - labels: list of string (optional)
  - assignees: list of string (optional)
  - custom_fields: map of string (optional)
Resource: github_testrun
  - identity: string (required)
  - rules: list of rule
Resource: github_testplan
  - identity: string (required)
  - runs: list of testrun
```

#### Modo JSON (`-json`):
Permite que extensiones de IDEs (VS Code, IntelliJ), linters o herramientas de automatización obtengan la estructura exacta de los recursos:

```bash
$ testform providers schema -json
```

```json
{
  "format_version": "1.0",
  "provider_schemas": {
    "registry.testform.io/fromeroc9/github": {
      "provider": { ... },
      "resource_schemas": {
        "github_testcase": { ... },
        "github_testrun": { ... },
        "github_testplan": { ... }
      }
    }
  }
}
```

### 5. `testform providers scaffold`

```bash
testform providers scaffold <nombre> [directorio] [--project]
```

Genera plantillas y código base estructurado para crear proveedores personalizados sin tener que escribir interfaces ni configurar el entorno desde cero.

#### Modalidad 1: Archivo Único `.ts` (Integración Rápida)
Genera un único archivo TypeScript tipado con la interfaz `IProvider`:

```bash
$ testform providers scaffold gitlab
Created custom-providers/gitlab.ts
```

Testform transpila este archivo de forma transparente al vuelo durante `testform plan` o `testform apply`.

#### Modalidad 2: Proyecto Completo Empresarial (`--project`)
Crea una estructura de proyecto independiente lista para Git o publicación en npm, incluyendo pruebas unitarias con Vitest:

```bash
$ testform providers scaffold gitlab --project
Created provider project structure in ./testform-provider-gitlab:
  - package.json
  - tsconfig.json
  - README.md
  - src/index.ts
  - src/client.ts
  - src/types.ts
  - test/provider.test.ts
```

### 6. `testform providers resource`

```bash
testform providers resource [acción] [nombre] [opciones]
```

Administra e inspecciona las plantillas de **recursos** (`ResourceTemplate`) asociados a los proveedores, permitiendo listar, visualizar o generar nuevas plantillas con tipado estricto:

#### Listar Recursos Registrados (`list`):
```bash
$ testform providers resource
# o testform providers resource list

REGISTERED RESOURCE TEMPLATES
────────────────────────────────────────
  • github_testcase
  • github_testrun
  • register-pokemon             [lifecycle hooks]
```

#### Generar Plantilla de Recurso (`scaffold`):
```bash
$ testform providers resource scaffold pokemon_trainer

✔ Successfully scaffolded custom resource template at:
  .testform/resources/pokemon_trainer.ts
```

El archivo generado contiene la definición completa de `attributes`, `state` y `lifecycle` hooks:

```typescript
import { ResourceTemplate, ParserScenario } from '@fromeroc9/testform';

export const pokemon_trainerResource: ResourceTemplate = {
    type: "pokemon_trainer",
    attributes: (scenario: ParserScenario) => ({
        title: scenario.name,
        description: scenario.description,
        tags: scenario.tags,
        ...scenario.custom?.fields
    }),
    state: {
        status: (scenario: ParserScenario) => scenario.custom?.fields?.status || 'active',
        synced_at: () => new Date().toISOString()
    },
    lifecycle: {
        beforeCreate: async ({ attributes }) => {},
        afterCreate: async ({ id, attributes, provider }) => {}
    }
};

export default pokemon_trainerResource;
```

#### Inspeccionar un Recurso (`show`):
```bash
$ testform providers resource show register-pokemon

Resource Template: register-pokemon
  Type:        register-pokemon
  Attributes:  function(scenario, context)
  State:       region, capturadoEn
  Lifecycle:   beforeCreate, afterCreate
```

## Opciones Generales del Comando

| Opción | Por Defecto | Descripción |
| :--- | :--- | :--- |
| `-test-directory=DIR` | `tests` | Directorio de pruebas de Testform donde buscar especificaciones. |
| `-var 'foo=bar'` | — | Define una variable en el módulo raíz. Puede usarse varias veces. |
| `-var-file=filename` | — | Carga variables desde un archivo (`testform.vars.yml` o `*.auto.vars.yml`). |

---

## Códigos de Salida

- `0`: Subcomando ejecutado exitosamente.
- `1`: Error de resolución de proveedores, ausencia de archivos de configuración o argumentos inválidos.
