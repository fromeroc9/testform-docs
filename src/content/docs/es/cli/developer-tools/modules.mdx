---
title: "testform modules"
description: "Muestra la lista de todos los módulos declarados y sus versiones resueltas en el espacio de trabajo."
---

```bash
testform [opciones globales] modules [opciones]
```

El comando `testform modules` inspecciona la configuración actual (`main.yml` y archivos de dominio) y muestra la lista de todos los módulos de prueba declarados en el espacio de trabajo de Testform junto con sus versiones resueltas y fuentes (`source`).

Sigue la misma filosofía, estructura de salida y formato JSON que `terraform modules`.

---

## Opciones del Comando

| Opción | Por Defecto | Descripción |
| :--- | :--- | :--- |
| `-json` | `false` | Emite la lista de módulos declarados y sus versiones resueltas en formato legible por máquina (JSON). |
| `-var 'foo=bar'` | — | Define un valor para una variable de entrada en el módulo raíz. Puede usarse varias veces. |
| `-var-file=filename` | — | Carga valores de variables desde el archivo indicado, además de los archivos por defecto `testform.vars.yml` y `*.auto.vars.yml`. |

---

## Ejemplos de Uso

### 1. Sin módulos declarados
Si no hay módulos declarados en la configuración:

```bash
$ testform modules
No modules found in configuration.
```

Y en formato JSON (`-json`):

```bash
$ testform modules -json
{"format_version":"1.0","modules":null}
```

### 2. Árbol de módulos declarados
Cuando existen módulos declarados en `main.yml` (mediante el bloque `module:` o `modules:`):

```yaml
version: "1.0"
module:
  auth:
    source: "./modules/auth"
  checkout:
    source: "./modules/checkout"
    version: "1.2.0"
  remote_qa:
    source: "git::https://github.com/my-org/qa-modules.git//auth?ref=v2.0.0"
```

Al ejecutar `testform modules`:

```bash
$ testform modules
Modules declared by configuration:
.
├── "auth"[./modules/auth]
├── "checkout"[./modules/checkout] 1.2.0
└── "remote_qa"[git::https://github.com/my-org/qa-modules.git//auth?ref=v2.0.0] v2.0.0
```

### 3. Salida en formato JSON (`-json`)

Permite a pipelines de CI/CD, linters y herramientas de auditoría parsear programáticamente las dependencias:

```bash
$ testform modules -json
```

```json
{
  "format_version": "1.0",
  "modules": [
    {
      "key": "auth",
      "source": "./modules/auth",
      "version": ""
    },
    {
      "key": "checkout",
      "source": "./modules/checkout",
      "version": "1.2.0"
    },
    {
      "key": "remote_qa",
      "source": "git::https://github.com/my-org/qa-modules.git//auth?ref=v2.0.0",
      "version": "v2.0.0"
    }
  ]
}
```

---

## Códigos de Salida

- `0`: Comando ejecutado exitosamente.
- `1`: Error de lectura o archivo de configuración malformado.
