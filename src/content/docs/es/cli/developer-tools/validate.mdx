---
title: "testform validate"
---

```bash
testform [opciones globales] validate [opciones]
```

El comando `testform validate` comprueba la sintaxis y coherencia de tus archivos de configuración (tanto los archivos `.feature` como `main.yml`). Valida que los pasos cumplan con la gramática de Gherkin, que los campos personalizados coincidan con los esquemas declarados y que no existan transgresiones de políticas.

La validación se realiza a nivel estrictamente local y **no** realiza peticiones a APIs remotas ni valida credenciales externas.

## Opciones del Comando

| Opción | Por Defecto | Descripción |
| :--- | :--- | :--- |
| `-target=target` | Ninguno | Valida únicamente un archivo `.feature` o recurso específico (ej. `-target=tests/smoke.run.feature` o `-target="auth/login.case.feature.@tc-1"`). |
| `-scope=scope` | `all` | Limita el alcance de validación a un scope específico (`testcase`, `testrun`, `testplan`, `bug` o `all`). |
| `-include=pattern` | Ninguno | Incluye únicamente features o escenarios que coincidan con el glob o tag (ej. `-include="tests/checkout/**"`, `-include=smoke`). |
| `-exclude=pattern` | Ninguno | Excluye features o escenarios que coincidan con el glob o tag (ej. `-exclude="tests/legacy/**"`, `-exclude=wip`). |
| `-severity=level` | `error` | Nivel mínimo de severidad para evaluar (`error`, `warning`, `advisory`). |
| `-strict` | `false` | Trata las advertencias (`warning`) de políticas como errores bloqueantes. |
| `-compact-warnings` | `false` | Muestra el recuento de advertencias de forma compacta sin el detalle individual. |
| `-json` | `false` | Emite diagnósticos en formato de objeto JSON, idóneo para linters de CI y Checks de GitHub. |
| `-no-tests` | `false` | Omite la ejecución de las políticas de calidad registradas. |
| `-test-directory=dir` | `tests` | Directorio que contiene los archivos de prueba. |
| `-query=texto` | Ninguno | Filtra escenarios que coincidan con la búsqueda. |
| `-no-color` | `false` | Desactiva colores en la salida de consola. |

## Ejemplos de Ejecución Real

### Validación Global (Todos los Scopes)
```bash
$ testform validate
Validating configuration...
Success! The configuration is valid.

  Scenarios: 8
  Scope:     all (testcase: 6, testrun: 1, testplan: 1)
```

### Validación de un Scope Específico
```bash
$ testform validate -scope=testcase
Validating configuration...
Success! The configuration is valid.

  Scenarios: 6
  Scope:     testcase
```

### Validación con Destino Específico (`-target`)
```bash
$ testform validate -target=tests/testrun/smoke.run.feature
Validating configuration...
Success! The configuration is valid.

  Scenarios: 1
  Scope:     testrun
```

### Advertencias de Esquema (Warnings)
```bash
$ testform validate
╷
│ Warning: Undeclared field 'tipo_prueba'
│ 
│   in tests/cart.case.feature:
│ The field 'tipo_prueba' is used but not declared in main.yml schema.
╵
Success! The configuration is valid, but there were some warnings.
```

### Fallo por Error Sintáctico o de Política
```bash
$ testform validate
╷
│ Error: Every scenario must have an identity tag matching the configured identity pattern.
│ 
│   in tests/login.case.feature:14
│ Add the identity tag (e.g. @tc-1) to each scenario.
╵
Error: The configuration contains errors.
```

### Validación Estricta de Proveedores (Terraform Parity)

`testform validate` comprueba que la declaración de proveedores y su estado local cumplan con las reglas de integridad:

#### 1. Proveedor no declarado en `required_providers`:
Si configuras un bloque `provider: jira:` en `main.yml` pero no lo declaraste en `testform.required_providers`:
```text
╷
│ Error: Undeclared provider "jira"
│ 
│ The provider is configured, but was not declared in testform.required_providers.
│ Run "testform init" to download and configure declared providers.
╵
```

#### 2. Proveedor no instalado en `.testform/providers/`:
Si un proveedor remoto está declarado pero no se ha descargado:
```text
╷
│ Error: Provider "gitlab" is not installed
│ 
│ Run "testform init" to download and install this provider.
╵
```

## Integración en Pre-Commit y Verificaciones de PR en CI/CD

Incorpora `testform validate -json` en tu flujo de trabajo de Pull Requests en GitHub Actions para prevenir el merge de sintaxis Gherkin defectuosa en las ramas principales:

```yaml
- name: Validar Configuración Test-as-Code
  run: testform validate -json
```

## Códigos de Salida

- `0`: Configuración válida (pueden existir advertencias).
- `1`: La configuración contiene errores de validación.
