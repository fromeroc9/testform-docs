Cuando trabajas con asistentes de código y agentes de inteligencia artificial (**Cursor**, **Claude Code**, **Antigravity**, **GitHub Copilot** o **Windsurf**), el modelo necesita conocer las directivas y convenciones del paradigma **Test-as-Code** para generar código 100% válido y libre de alucinaciones.

Testform proporciona un manual de reglas estandarizado y universal que puedes colocar directamente en la raíz de tu proyecto.

## 📐 Las 4 Primitivas y sus Reglas Estrictas

### 1. Casos de Prueba (`*.case.feature`)
* **Cabecera**: Debe iniciar con `@testcase` en la línea de `Feature:`.
* **Restricción de Tags en Feature**: **Prohibido** colocar tags funcionales libres (como `@smoke`, `@regression`) en la línea `Feature:`. Solo se permite `@testcase` y opcionalmente `@ns(nombre)`. Todos los demás tags van en cada `Scenario:`.
* **Identidad Secuencial**: Cada escenario debe tener una etiqueta `@tc-*` (`@tc-01`, `@tc-02`).
* **Estructura BDD Obligatoria**: Cada escenario **debe** incluir al menos un paso `Given`, `When` y `Then`.
* **Cero `* set`**: **Estrictamente prohibido** cualquier paso `* set` (incluyendo `attach`). Para metadatos de contrato utiliza `* field <nombre> = <valor>`.

### 2. Corridas de Prueba (`*.run.feature`)
* **Cabecera**: Debe declarar `@testrun @tr-01` en la línea `Feature:`.
* **Soporte de Estructuras**: Admite con `Rule: <path.case.feature>` (`Scenario: @tc-01`) o sin `Rule:` usando dirección canónica (`Scenario: tests/features/login.case.feature.@tc-01`).
* **Background**: Admite marcas de ejecución de suite (`* set duration = "1m 20s"`, `* set attach = "..."`, `* set trace = "..."`). **Prohibido declarar `set status` en Background** (el estado de la suite se autocalcula automáticamente a partir de sus escenarios).
* **Escenarios**: Declaran estrictamente `* set status = <passed|failed|pending|blocked|skipped|undefined|ambiguous>`.
* **Anti-patrón**: **NO** uses pasos `Given`, `When`, `Then` dentro de un `@testrun`. Las corridas son orquestaciones de resultados, no definiciones de comportamiento.

### 3. Planes Maestros (`*.plan.feature`)
* **Cabecera**: Debe declarar `@testplan @tp-01` en la línea `Feature:`.
* **Estructura**: Agrupa las suites y corridas mediante bloques `Rule:`.
* **Adjuntos**: Únicamente permitidos en `Background:` (`* set attach = ...`). El estado del plan es autocalculado (*rollup*).
* **Integridad**: Un mismo `@testrun` no debe asignarse a más de un plan maestro.

### 4. Defectos y Bugs (`*.bug.feature`) — Soporte Exploratorio y Trazable
* **Cabecera**: Debe iniciar con `@bug` (no coloques `@adhoc` ni `@smoke` en la línea `Feature:` por `no-feature-tags`).
* **Background**: Permite opcionalmente `* set run = testruns/...run.feature` para vincular con la corrida ejecutada (en sesiones **exploratorias** puede omitirse por completo).
* **Trazabilidad Defecto $\rightarrow$ Testcase u Opcionalidad Exploratoria**:
  * Con caso conocido bajo `Rule: <path.case.feature>`: `@bg-01 @depends_on(@tc-01)` (o `@bg-01 @tc-01`).
  * Sin `Rule:`: dirección canónica `@bg-01 @depends_on("path.case.feature.@tc-01")`.
  * En **pruebas exploratorias**: agrega `@adhoc`, `@exploratory` o `@independent` en el `Scenario:` (ejemplo: `@bg-02 @adhoc`) o declara `* set trace` para omitir `@depends_on` sin advertencias de `bug-target-integrity`.
* **Escenario**: A diferencia de `@testrun`/`@testplan`, un `@bug` **sí admite pasos opcionales `Given/When/Then/And/But`** de reproducción junto con `* set status = open | in_progress | resolved | closed`, `* set attach = ...`, `* set trace = ...` y `* field <nombre> = <valor>`.

## 📎 Matriz de Gobernanza de Adjuntos (`* set attach`)

La directiva `* set attach = "attachments/..."` sigue reglas de ubicación estrictas validadas por la política `attach-governance`:

| Recurso | ¿Permitido en `Background:`? | ¿Permitido en `Scenario:`? | Motivo de la Regla |
|---|:---:|:---:|---|
| **`testcase`** | ❌ **PROHIBIDO** | ❌ **PROHIBIDO** | `* set` está prohibido en testcases; los casos son especificaciones puras de comportamiento BDD. |
| **`testrun`** | ✅ **SÍ** | ❌ **PROHIBIDO** | `Background` para logs y artefactos del ambiente (`exec.log`). Los escenarios solo declaran status. |
| **`testplan`** | ✅ **SÍ** | ❌ **PROHIBIDO** | Los criterios de release y documentación son globales del plan maestro. |
| **`bug`** | ❌ **PROHIBIDO** | ✅ **SÍ** | Las evidencias de un bug deben pertenecer al defecto puntual, nunca a precondiciones globales. |

## 🚫 Anti-Patrones que la IA Debe Evitar

1. ❌ **No usar `* set` en `*.case.feature`**: Los casos de prueba no llevan ninguna sentencia `set`. Usa `* field` para gobernanza.
2. ❌ **No definir como `* field` campos con `source: "tag"` en `main.yml`**: Campos como `priority` configurados con `source: "tag"` deben declararse como etiquetas `@tag` (ej. `@medium`).
3. ❌ **No declarar `* set status` en `Background:` de un `@testrun`**: El estado de la suite es autocalculado por el motor.
4. ❌ **No inventar pasos `Given/When/Then` en `@testrun` o `@testplan`**: Esos archivos usan asignación de estados y referencias.
5. ❌ **No colocar adjuntos en `Background:` de archivos `@bug`**: El validador emitirá un error bloqueante.
6. ❌ **No omitir `Given/When/Then` en `*.case.feature`**: Toda especificación de caso de prueba requiere la estructura BDD completa.
7. ❌ **No duplicar números de identidad**: Siempre inspecciona el proyecto para asignar el siguiente número correlativo (`@tc-03` si ya existen `@tc-01` y `@tc-02`).
