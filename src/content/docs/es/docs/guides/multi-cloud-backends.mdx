---
title: "Backends Multi-Cloud"
description: "Configura el almacenamiento remoto del estado de Testform en OCI, AWS S3, Azure Blob Storage y Google Cloud Storage usando la sintaxis en modo diccionario."
---

Configura el almacenamiento remoto y seguro del ledger de estado (`testform.state`) en la nube de tu preferencia dentro de `main.yml` usando **modo diccionario** bajo `testform.backend`.

> [!IMPORTANT]
> Cualquier backend remoto requiere ejecutar `testform init` antes de usar `plan`, `apply`, `refresh` o `destroy`. Para conocer las reglas completas del bloque `backend`, consulta [Backends y Almacenamiento de Estado](/testform-docs/es/docs/language/backends/).

## 1. Oracle Cloud Infrastructure (OCI Object Storage)

El backend de OCI almacena el estado en un bucket de Object Storage compatible con S3 utilizando endpoints regionales por `namespace`:

```yaml
# main.yml
testform:
  required_version: ">= 1.0.0"
  backend:
    oci:
      namespace: "mi-tenancy-namespace"
      bucket: "testform-state"
      key: "produccion/testform.state"
      region: "us-ashburn-1"
```

Variables de entorno S3-compatibles de OCI (Customer Secret Keys):
- `AWS_ACCESS_KEY_ID`
- `AWS_SECRET_ACCESS_KEY`
- `AWS_REGION`

## 2. Amazon Web Services (AWS S3 + DynamoDB)

Utiliza un bucket de S3 para almacenar el archivo de estado y una tabla de DynamoDB opcional para el bloqueo distribuido con mutex:

```yaml
# main.yml
testform:
  required_version: ">= 1.0.0"
  backend:
    s3:
      bucket: "empresa-testform-tfstate"
      key: "core/testform.state"
      region: "us-east-1"
      dynamodb_table: "testform-locks"
      encrypt: true
```

Variables de entorno requeridas:
- `AWS_ACCESS_KEY_ID`
- `AWS_SECRET_ACCESS_KEY`
- `AWS_REGION`

## 3. Microsoft Azure Blob Storage (`azurerm`)

Almacena el estado en Azure Blob Storage con arrendamiento exclusivo (*blob leases*) para garantizar exclusión mutua:

```yaml
# main.yml
testform:
  required_version: ">= 1.0.0"
  backend:
    azurerm:
      resource_group_name: "rg-testform-qa"
      storage_account_name: "empresatestform"
      container_name: "tfstate"
      key: "qa/testform.state"
```

Variable de entorno requerida:
- `AZURE_STORAGE_CONNECTION_STRING` (o `connection_string` mediante `-backend-config` sin commitear secretos en Git).

## 4. Google Cloud Storage (`gcs`)

Utiliza GCS con precondiciones de generación (`ifGenerationMatch: 0` sobre `<state>.tflock`) para bloqueos concurrentes:

```yaml
# main.yml
testform:
  required_version: ">= 1.0.0"
  backend:
    gcs:
      bucket: "empresa-testform-state"
      prefix: "qa-environments"
```

Variable de entorno requerida:
- `GOOGLE_APPLICATION_CREDENTIALS=/path/to/service-account.json`
